# CANONICAL-SOURCES.md — каноническая модель источников

Этот файл — арбитр. Он отвечает на один вопрос: **какой файл считается источником истины,
если один и тот же Блок представлен и верхним файлом `NN-….md`, и подпапкой `NN/`.**

## Зачем этот файл существует

После нарезки крупных Блоков в каталоге `architecture/` сосуществуют:

- верхние файлы общего ряда (`10-lifecycle-return.md`, `15-content-antipiracy.md`,
  `17-author-panel.md`, `99-legal.md`);
- подпапки с частями (`10/`, `15/`, `17/`, `99/`).

Для человека это читаемо (индекс + части). Для AI-агента без явного правила это опасно:
он находит две версии одного Блока и не понимает, какая каноническая.
Настоящий файл снимает эту двусмысленность.

## Каноническая модель крупных Блоков

| Блок | Верхний файл | Подпапка | Роль верхнего файла | Роль подпапки | Победитель при расхождении |
|---|---|---|---|---|---|
| 10 | `10-lifecycle-return.md` | `10/` | вводная + оглавление частей | посекционный носитель содержания | файлы из `10/` |
| 15 | `15-content-antipiracy.md` | `15/` | единая сборка (обзор) блока | посекционный носитель содержания | файлы из `15/` |
| 17 | `17-author-panel.md` | `17/` | вводная + оглавление частей | посекционный носитель содержания; YAML-контракт `block_17` в `17-99-yaml-full.md` перенесён дословно из исходника | файлы из `17/` |
| 99 | `99-legal.md` | `99/` | вводная + навигация | посекционный носитель содержания; среди частей 99 старшая — `99-03-yaml-v2ext.md` (правило самого блока) | файлы из `99/` |

## Правило чтения для агента

Если задача касается Блока 10, 15, 17 или 99:

1. открыть верхний файл (получить контекст и оглавление);
2. открыть нужную часть из подпапки `NN/`;
3. работать по содержанию из подпапки;
4. если верхний файл говорит одно, а часть — другое, приоритет у части.

Нормативный стек (`I1…I4`, `B17`, `SEAM-PATCH-1`, `ERRATA-UNIFIED`) — над всеми верхними
файлами и над всеми подпапками. Порядок старшинства зафиксирован в
[normative/README.md](normative/README.md); настоящий файл его не переопределяет.

Особенность для Блока 17: YAML-контракт `block_17` в `17/17-99-yaml-full.md` является
машиночитаемым и **должен оставаться байт-в-байт равным** соответствующему разделу
исходного `17-author-panel.md`. Любое сокращение YAML — регресс правила нулевых потерь.

## Что считается нарушением этой модели

1. Верхний файл крупного Блока (10/15/17/99) содержит норму, которой нет ни в одной части, и
   не помечен явно как «единая сборка» или «вводная».
2. Агент ссылается на `_WIP-architecture-split.md` как на источник истины (это исторический
   служебный журнал; действующий реестр дефектов — `appendix/D-source-defects.md`).
3. В `AGENTS.md`, `CONTEXT.md` или корневом `README.md` не отражено правило
   «верхний файл — индекс, подпапка — канон».
4. Файл `17/17-99-yaml-full.md` содержит сокращения или переформатирование YAML-контракта
   `block_17` (стережётся ручной сверкой при первом изменении Блока 17).

## Правило нулевых содержательных потерь

Любая новая нарезка/пересборка допустима только если выполнены все пункты:

1. все заголовки исходного файла перенесены (grep по `^#` до и после);
2. все таблицы перенесены (сравнение количества строк матриц);
3. все YAML-блоки перенесены целиком, без сокращений (сравнение размера в байтах);
4. все относительные ссылки перепроверены;
5. верхний файл после нарезки не содержит норм, которых нет в частях;
6. контроль `bash tools/checks.sh` проходит зелёным.
